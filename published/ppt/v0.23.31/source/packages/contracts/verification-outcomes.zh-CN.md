# 验证结果解释 — v0.18.2

分别判断工具是否正常运行、记录是否完整有效、实际成品是否存在质量问题。
使用现有 checks、校准 findings、审计 coverage 和 work-notes，不新增人工审批表
或整稿发布门槛。

| 观察到的情况 | 结论与处理 |
| --- | --- |
| 工具抛异常或未完成 | 工具异常，该检查尚未取得成品质量结论；保留命令和原始错误，修复原因后重跑受影响项。 |
| 规则无法处理受支持的格式 | 适用范围或兼容问题；保留原始失败，独立绑定后续核验证据，不静默改为通过。 |
| 身份、绑定、来源证据或必需记录结构缺失、无效 | 完整性缺陷；修复记录后重新验证，不能用质量意见代替缺失证据。 |
| 内容、口径、数字、可读性或编辑行为实际有误 | 成品质量缺陷；引用具体句子、对象或页面，交回最早责任阶段。 |
| 检查正常完成且通过 | 仅该项及实际覆盖范围通过，不扩大为全稿内容或设计通过。 |

工具原始结果、独立核验结论、实际修复状态分别保留。声明 fail 本身不等于记录
格式错误；deferred、uncertain 保留未验范围。未知状态值和自相矛盾的 pass
声明仍是记录错误。issues_remaining 非空不因存在问题而变成语法错误，但仍
不能得到全部通过的 QA 结论。记录有效不等于成品无缺陷。

原生比对、Output QA 和偏差记录验证器支持 --result-json <路径>，自动写出诊断，
保留现有控制台输出。诊断分别记录运行 completed/error/not-run、记录验证
valid/invalid/unverified、该检查范围内的质量 pass/fail/unverified 及原始消息。
已有非零结果仍为非零。偏差记录结构通过不代表 PPTX 质量通过；允许额外文字的
诊断模式不能作为最终验收。

工具修复后保留旧结果与真实失败。异常本身不能授权通过，也不能直接推断正文错误。
按证据修复后仅重验受影响检查或页面，未变的确定性证据可以复用。继续遵循用户
明确的发布条件和绑定完整的交付政策，不另加审批循环。
