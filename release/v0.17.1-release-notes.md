# Clayz Presentation Skills v0.17.1

This release strengthens the interaction and review between presentation stages, keeping the argument, wording, visual plan, and final slides connected. It supports language models and agent environments through shared skills, contracts, and tools.

## Stage interaction and audit

- **Logic → Copy:** Logic hands over a complete, source-backed narrative. Copy owns pagination and audience-facing language while preserving facts, reasoning, and necessary qualifications. Missing analysis goes back to Logic rather than being hidden by shorter wording.
- **Copy → Art Direction:** the visual stage receives the approved copy and produces a complete set of page images plus a matching specification. Layout must make room for necessary explanations; content changes return to Copy or Logic.
- **Art Direction → Output:** Output implements the locked images and specification as editable slide objects. Changes outside the allowed adjustments return to the responsible stage instead of silently changing the design.
- **Supervisor at each handoff:** stage artifacts go to both the next owner and Supervisor. Three calibration checkpoints preserve feedback, downstream decisions, and artifact bindings so that requirements and corrections remain traceable.
- **Independent audit after Output:** review the written presentation and available renders against the original requirements and design baseline. Content fidelity, visual fidelity, editability, and design quality remain separate observations. Supervisor receives the findings and makes the delivery decision.

## Readable content and inspectable delivery

Necessary explanation takes priority over arbitrary brevity or uniform sentence patterns. Reviewers read the argument, visible copy, and actual pages; data or layout checks alone do not establish language quality.

The source-bound work report retains stage documents and review evidence. Readable reports and the stage-handoff archive provide the narrative, final copy, visual specification, image drafts, and available side-by-side comparisons. Missing evidence and unperformed checks remain explicit. Quality findings are handled according to the task's delivery policy rather than automatically becoming blanket production blockers.

## Packages

Cloud Public Light, Local Public Light, the Windows CPython 3.12 offline dependency add-on, and SHA-256 checksums. Generation and rendering capabilities depend on the host's available tools.

## 中文说明

v0.17.1 重点加强制作环节之间的交互、校准与审计，让论述、文案、设计稿和最终幻灯片保持一致。不同大模型和 Agent 环境可通过通用技能、合同与工具使用这套流程。

### 环节之间如何交接与复核

- **Logic → Copy：** Logic 交付有来源支撑的完整论述；Copy 负责分页和面向读者的表达，保留事实、推理与必要限定。缺少分析时回到 Logic，不靠压缩文字掩盖。
- **Copy → Art Direction：** 设计阶段接收批准文案，形成整套逐页图片稿及一致的视觉规格。排版为必要解释提供空间，涉及内容变化时回传 Copy 或 Logic。
- **Art Direction → Output：** Output 按锁定图稿和规格实现可编辑对象；超出允许微调范围的变化交回责任环节，不静默改动构图或内容。
- **Supervisor 贯穿交接：** 每份阶段产物同时送往下一环节与 Supervisor。三轮校准记录评价、下游处理决定和文件绑定，让要求与修正可以追溯。
- **Output 后独立审计：** 对照原始要求与设计基准，检查实际写盘文件和可用渲染。内容保真、视觉保真、原生可编辑性与设计质量分别记录；Supervisor 接收审计发现并决定交付。

### 让内容读得懂，让交付查得清

必要解释优先于单纯追求字少、对仗或统一句式。审阅者实际阅读论述、可见文案和页面，不能把数据或版式检查通过等同于语言质量通过。

工作报告保留原始阶段文档及审阅依据。可读报告和阶段交接压缩包提供完整论述、最终文案、视觉规格、整套图片稿及可用的并排对照。缺失证据、未执行检查明确披露；质量问题按任务交付政策处理，不自动成为全面阻断制作的理由。

发布内容包括 Cloud Public Light、Local Public Light、Windows CPython 3.12 离线依赖附加包及 SHA-256 校验清单。实际生成与渲染能力取决于宿主可用工具。
