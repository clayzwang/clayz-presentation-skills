# 来源吸收边界

Clayz 把概念、公开 API、可选依赖和再分发文件分开管理。“受到启发”绝不等于“静默复制”。

## 截至 v0.3.0 已吸收

| 来源 | 吸收内容 | 不吸收/不捆绑 |
|---|---|---|
| PPT Master | 后续参考的原生可编辑PPT工作流、演示资产分类和来源治理方法 | 上游代码、提示词、知识文档、模板、图表、表格、图标、样例PPTX、数据集、模型和媒体；本仓库均不捆绑 |
| PPTAgent | 有限动作、执行历史、参考结构拆解、定向重试思想 | 提示词、编排代码、参考页、模型、工具、数据集 |
| DeepPresenter | 环境观察、分面反思、能力缺口显式化 | 权重、任务集、沙箱镜像、Agent运行时、提示词、外部服务 |
| pom | 声明式相对布局树、固定与弹性区域、源—预览—构建分离 | pom XML、Yoga 源码、软件包、主题、母版生成、节点实现 |
| VASCAR | 有限的渲染—观察—修正诊断循环 | 论文图片、代码、数据、评分模型、自动选优 |
| PptxGenJS | 面向可编辑对象的公开 API 映射 | 默认启用运行、依赖锁、软件快照、演示文件、模板、母版、媒体；v0.2.0 因间接依赖未修复而保持安全阻断 |
| PosterO | 设计意图与层级布局树研究思想 | 仓库代码、权重、数据集、标注、显著性流程、论文图片、版式 |
| PosterLayout | 内容感知的主体保护、放置、重叠与可读性观察词汇 | 仓库代码、模型、数据集、标注、指标、论文图片、版式、媒体 |
| Scan-and-Print | 局部放置适配度与候选区域观察思想 | 仓库代码、模型、数据集、局部块、标注、论文图片、版式、媒体 |
| CreatiPoster | 前景／背景分离与可编辑分层构图思想 | 仓库代码、协议、模型、数据集、训练方法、论文图片、版式、字体、媒体 |
| 来自 IBM、Microsoft、Google Cloud、AWS、Oracle、SAP、NVIDIA、Databricks、Snowflake 与 Apple 的 76 份官方架构材料 | 来源索引、关系标签、16 张模式卡和八步“语料—模式—综合”方法 | 架构图、原文、产品图标、品牌视觉、母版、模板、坐标和媒体 |

## 主动排除

本项目不吸收 reveal.js、Marp、PosterLlama、Typst/Paged、外部母版体系、自动审美真值或模型权重，也不附带真实PPT案例。这是产品边界，不是等待补齐的遗漏。

每个吸收来源都在 `provenance/manifest.yaml` 记录准确链接、论文、审阅版本/提交、已知许可、影响范围和再分发声明；`provenance/THIRD_PARTY_NOTICES.md` 与 `NOTICE` 公开致谢，并在真正产生影响的 reference 中就近引用。
