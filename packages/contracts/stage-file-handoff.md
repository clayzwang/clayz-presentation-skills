# Professional stage files — 1.0

New work uses content package 3.5. This extends the existing five stages, not a second production controller. Logic receives only topic, audience, research requirements and task materials. Copy receives full research files and editorial requirements; Art receives the actual account/text and formatting requirements; Output receives actual design files and delivery requirements. Supervisor retains full runtime/configuration and exception records separately.

Logic must deliver an expanded full research report plus an observable process log, source/evidence ledger and data file. A summary or numbered findings list cannot substitute for research. The report's natural structure follows the evidence and task; there is no fixed question, paragraph or finding count.

Copy saves its complete reader-facing account and registers it before creating the page document. The page file binds that actual account record, traces every text unit to real character spans, and records substantive editing/meaning judgments. No automatic heading level, heading count, group count, equal-peer assumption or layout is inferred from tuple/list shape. Rereading concatenated pages is useful only as a later check; it cannot become the pre-pagination account.

Art decides grouping from actual meaning and the user's design requirements, not the number of Copy headings. Preserve original Copy and documented Art changes. Output retains the real editable PPTX, PDF, all page renders, native QA and exceptions. File binding does not approve research or visual quality; existing professional readings and native checks remain responsible.

Use scripts/stage_documents.py files-* for immutable file records. files-prepare uses role-specific brief allowlists. files-research, files-account, files-copy, files-art, files-output and files-supervisor bind the actual files. files-collect copies user input, actual tool/knowledge version records and all stage evidence for later model analysis. It does not run training. Subsequent iterations improve reusable foundational methods and actual tool/knowledge bytes; they do not promote case-specific repairs into default methods.

files-bind-logic and files-bind-copy are Supervisor/tool operations for the existing machine validation and reporting path. Their runtime envelopes are not professional author inputs. Legacy packages require explicit replay, not silent new-run fallback.

For exact file roles and operational details, read the locale-matched Chinese contract when working in zh-CN.

Material collection also requires --tool-snapshot and --knowledge-snapshot. Retain actual version bytes, not names alone. Supervisor adds the actual runtime bindings, calibrations, original reader responses/confirmations, Auditor and report files using repeatable --supporting-artifact arguments; they are not author inputs. Unperformed checks remain unperformed. files-check-collection verifies saved bytes and nested file completeness after original paths move; read_collected_file reads those portable copies.
