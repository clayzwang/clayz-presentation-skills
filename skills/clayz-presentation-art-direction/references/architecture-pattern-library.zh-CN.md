## 模式卡

### 1. 结果—地基房子图

- **回答的问题：** 哪些有序能力和共享控制共同支撑一个经营结果？
- **关系语法：** 结果屋顶 → 能力楼层 → 运行地基，共享控制跨越多个楼层。
- **来源信号：** IBM 能力模型、SAP North Star、Oracle 数据平台和云登陆区架构。
- **ChatBI 适配：** 屋顶放决策质量与业务行动；下方依次放调查、可执行语义、数据计算和基础设施。
- **综合动作：** 先依据依赖关系与证据转换确定楼层顺序，再从当前业务问题中提炼屋顶、支柱和地基名称。

### 2. 证据阶梯

- **回答的问题：** 企业原始现实如何变成可负责的决策？
- **关系语法：** 事件或记录 → 受治理数据 → 业务意义 → 证据 → 假设 → 判断 → 批准的行动。
- **来源信号：** 分析流水线、文档智能、AI 治理与数据产品架构。
- **ChatBI 适配：** 在检索和判断之间显式表达来源、有效期、指标粒度、反证与不确定性。
- **综合动作：** 为每条转换写一个可检验动词；无法命名的转换应拆开或删除。

### 3. 构建态—运行态分流

- **回答的问题：** 哪些工作准备知识，哪些工作实时回答问题？
- **关系语法：** 摄取/索引/评估路径与查询/检索/推理/响应路径并列，通过版本化知识资产连接。
- **来源信号：** IBM、Google Cloud、Oracle、NVIDIA 和 Microsoft 的 RAG 架构。
- **ChatBI 适配：** 将指标定义、语义版本、测试用例和来源索引与交互式调查、决策支持分开。
- **综合动作：** 把共享资产放在中心，并标出谁负责把它发布到运行态。

### 4. 生产者—平台—消费者网格

- **回答的问题：** 分布式责任主体如何共享可信数据，同时避免中央瓶颈？
- **关系语法：** 领域生产者 ↔ 自助平台/目录 ↔ 消费者，外部由联邦治理约束。
- **来源信号：** Google Cloud 数据网格、AWS 数据网格、Oracle 去中心化平台和 Databricks 治理。
- **ChatBI 适配：** 业务领域拥有定义和证据；认知平台负责赋能与仲裁，不拥有业务真相。
- **综合动作：** 为每个边界交换物命名：指标、数据产品、证据包或获批行动。

### 5. 平台平面—工作负载平面

- **回答的问题：** 哪些能力集中共享，哪些能力保留在具体业务场景？
- **关系语法：** 共享平台平面位于多个工作负载平面之下或侧面，提供继承服务和护栏。
- **来源信号：** Azure 与 Google Cloud 登陆区、NVIDIA AI 工厂和 Databricks 平台架构。
- **ChatBI 适配：** 身份、可观测、模型访问、语义注册、证据账本和发布机制共享；问题、假设、决策权和行动按场景保留。
- **综合动作：** 用不同连接语义区分“继承”与“运行时数据流”。

### 6. 横切控制轨

- **回答的问题：** 哪些关注点同时约束多个阶段，而不是一个孤立方框？
- **关系语法：** 用纵向支柱或横向轨道表达治理、安全、质量、来源、成本与可观测。
- **来源信号：** IBM 数据织物、AWS Analytics Lens、SAP North Star、Oracle 数据平台和 Databricks 治理。
- **ChatBI 适配：** 表达谁定义、执行、观察、质疑和回滚，而不是只写“治理”。
- **综合动作：** 将控制轨连接到确实受其约束的阶段，并标注约束机制。

### 7. 成熟度或奖牌式递进

- **回答的问题：** 资产如何经过有序阶段变得更可用、更可信？
- **关系语法：** 原始/铜 → 统一/银 → 策展/金 → 语义就绪或行动就绪。
- **来源信号：** Microsoft Fabric、Snowflake 流水线、Databricks、AWS Analytics Lens 和 Oracle Lakehouse。
- **ChatBI 适配：** 从源记录递进为核对事实、指标证据和决策主张。
- **综合动作：** 为每一阶段写清质量提升与责任提升。

### 8. 语义中介核心

- **回答的问题：** 什么把技术数据转成稳定的业务含义？
- **关系语法：** 一侧是来源和模型，另一侧是用户和决策，中间包含对象、关系、指标、策略、血缘和有效时间。
- **来源信号：** SAP Knowledge Graph、Snowflake 语义视图、IBM 数据织物、Oracle Analytics 与企业目录。
- **ChatBI 适配：** 区分术语匹配与能计算、核对、追溯、版本化的可执行语义。
- **综合动作：** 至少展示一条穿过语义核心的“对象—关系—指标”实例链。

### 9. 人类决策门

- **回答的问题：** 模型辅助在哪里结束，组织责任从哪里开始？
- **关系语法：** 模型建议 + 证据 + 不确定性 → 具名人类角色 → 批准/质疑/修订/升级 → 可负责行动。
- **来源信号：** IBM AI 治理、Microsoft 人工复核、SAP 验证方法和 Apple 责任边界。
- **ChatBI 适配：** 模型可以检索、计算、比较、提出假设和建议；具名角色裁定定义、冲突、例外与行动。
- **综合动作：** 把决策权画成门，标明输入、可能结果和责任人。

### 10. 受治理反馈飞轮

- **回答的问题：** 业务结果如何改进系统，又不悄悄改写真相？
- **关系语法：** 生产结果 → 观察 → 归因 → 专家裁决 → 回归测试 → 版本发布 → 效果监测 → 回滚路径。
- **来源信号：** IBM 监测、NVIDIA 数据飞轮、Microsoft DataOps、Google 质量评估子系统和 SAP 验证。
- **ChatBI 适配：** 把证据与已裁决修正分别反馈到指标、语义合同、检索资产和调查方法。
- **综合动作：** 每一步都标明发生变化的资产和批准变化的角色。

### 11. 调查编排循环

- **回答的问题：** 开放式经营问题如何变成有边界的分析？
- **关系语法：** 情境 → 假设 → 工具调用 → 证据与反证 → 不确定性检查 → 停止条件 → 建议。
- **来源信号：** Agentic AI、Agentic RAG、AI-Q Research Agent 和模块化 LLM 编排。
- **ChatBI 适配：** 查询只是调查工具之一；同时表达矛盾处理、范围控制和停止条件。
- **综合动作：** 显示调查循环，但把业务批准留在循环之外。

### 12. 混合边界图

- **回答的问题：** 数据、控制与责任在哪里跨越组织或基础设施边界？
- **关系语法：** 企业、云、领域、伙伴或边缘形成边界区；数据、控制、身份和反馈使用不同类型连接。
- **来源信号：** Oracle 多云、IBM 混合架构、AWS 工业边缘、Google 混合基础和 Apple 部署。
- **ChatBI 适配：** 区分远程访问、证据复制、联邦查询和获授权的业务行动。
- **综合动作：** 为每条跨边界连接同时标明机制与责任人。

### 13. 登陆区层级

- **回答的问题：** 策略与共享服务如何扩展到多个环境和业务工作负载？
- **关系语法：** 企业或租户根 → 平台地基 → 环境或领域区 → 工作负载实例，并逐级继承策略。
- **来源信号：** Microsoft、Google Cloud 登陆区，Oracle Compartments 和 NVIDIA Scale Units。
- **ChatBI 适配：** 先把企业认知治理映射到共享服务，再展示不同领域、场景和发布阶段的生产空间。
- **综合动作：** 用不同连线区分组织层级与运行时流向。

### 14. 生命周期传送带

- **回答的问题：** 架构如何被构建、发布、运行、观察和修改？
- **关系语法：** 发现 → 定义 → 构建 → 测试 → 发布 → 运行 → 观察 → 改进。
- **来源信号：** Microsoft DataOps、SAP 方法论、NVIDIA 部署指南和云 Well-Architected 框架。
- **ChatBI 适配：** 让语义定义、证据测试、调查方法和用户体验作为不同资产穿过生命周期。
- **综合动作：** 为每一阶段附上负责人、进入条件、输出资产和反馈去向。

### 15. 能力分解图

- **回答的问题：** 企业需要哪些能力，同时不暗示不存在的流程顺序？
- **关系语法：** 面向结果的能力域 → 二级能力组 → 三级能力，依赖关系另行表达。
- **来源信号：** IBM GenAI 能力模型、SAP 数据能力与云采用框架。
- **ChatBI 适配：** 用于界定范围与成熟度；涉及因果时与证据阶梯或生命周期组合。
- **综合动作：** 先按责任与结果归组，再只补充会影响决策的依赖。

### 16. 可观测性与质量覆盖层

- **回答的问题：** 架构可靠性如何被证明？
- **关系语法：** 指标、追踪、血缘、质量测试、成本、风险和用户结果跨越构建态与运行态。
- **来源信号：** NVIDIA RAG 容量方法、云 Well-Architected 框架、IBM 治理和 Databricks 质量指南。
- **ChatBI 适配：** 观察来源新鲜度、语义版本、计算可复现性、检索证据、答案不确定性、决策时延和实际结果。
- **综合动作：** 在被测机制旁放置信号，再汇总为管理视图。

## 组合方法

选择一个决定阅读路径的**主骨架**、一个表达责任的**控制模式**，必要时再选择一个解释变化的**演进模式**。ChatBI 房子图常用组合是：

- 用“结果—地基房子图”作为主骨架；
- 用“语义中介核心”和“调查编排循环”表达内部机制；
- 用“横切控制轨”和“人类决策门”表达责任；
- 用“受治理反馈飞轮”表达演进。

在任务研究账本中记录所选模式、来源 ID、适配决定和被舍弃的替代方案。
