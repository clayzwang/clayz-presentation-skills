# 设计意图布局树

当页面包含嵌套语义、主视觉锚点、受保护留白，或关系不应被压平成同级矩形时，使用本路由。

本抽象受到 [PosterO](https://openaccess.thecvf.com/content/CVPR2025/html/Hsu_PosterO_Structuring_Layout_Trees_to_Enable_Language_Models_in_Generalized_CVPR_2025_paper.html) 关于结构化布局树与设计意图的研究启发。Clayz 不复制或运行其代码、数据集、标注、权重、论文图片、显著性流程或生成版式。其公开仓库没有清晰的仓库级许可证，因此这里只进行论文引用和独立表达；准确边界记录在 `provenance/manifest.yaml`。

## 先说明意图，再确定几何

选择坐标前先写清：

- 受众首先应注意什么；
- 哪些元素属于同一语义组；
- 关系是顺序、比较、包含、因果、层级还是注释；
- 哪个视觉或内容区域必须避免遮挡；
- 哪个区域可吸收文案或媒介变化；
- 系列页允许改变什么、必须持续什么。

设计意图只是需要接受 Logic 与 Copy 检验的假设。检测器、显著性图、相似度和模型标签都只是辅助证据。

## 树语法

- 根节点表达整页沟通任务，不是泛化画布。
- 内部节点表达分组、包含、阅读顺序、对齐或叠层。
- 叶节点绑定批准的 `copy_id` 或批准的非文字对象。
- `role` 表达功能，`intent` 说明节点存在的原因。
- `protected=true` 标记不可被子节点侵占的语义留白或主体区域。
- 树可使用 `row`、`column`、`grid`、`layers`，但这些词不是自动选择构图的组件库。

每个批准文案必须且只能映射一次。父子关系必须保留到对象分组和最终阅读顺序。不同关系不得为了制作方便而套入同一种容器。

## 内容感知

照片或插画画布需要判断主体、运动方向、视觉重量与安全文字区；不得宣称通用显著性工具理解了演示意图。数据页要把绘图区、标签、注释和来源视为不同语义区域，即使它们共同属于一个图表。

## 交接与证明

使用 `packages/contracts/layout-tree.schema.json` 导出批准树，Output 可运行：

```bash
python packages/layout/solve_relative_layout.py layout-tree.json resolved-layout.json
```

求解器只分配已经批准的关系并报告不可行约束，不负责选择视觉方案，不得静默缩字、侵占留白或替代真实渲染 A/B。最终证据必须比较批准树、可编辑对象层级和实际渲染阅读顺序。
