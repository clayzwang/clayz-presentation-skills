# 参考架构综合方法

本方法用于能力房子图、企业总体架构、数据或 AI 平台全景图和经营系统架构。它把大规模一手资料转化为面向具体问题的独立架构。

## 载入研究资源

1. 读取 `architecture-source-index.json`，使用已审阅的 76 份官方材料索引。
2. 读取 `architecture-pattern-library.zh-CN.md`，使用可复用的关系语法。
3. 在任务目录建立研究账本，不把来源架构图复制进技能或交付物。

## 方法

### 1. 界定架构问题

分别用一句话写清：

- 图要支撑的决策或经营结果；
- 受众与决策时间尺度；
- 系统边界；
- 必须被讲明白的转换过程；
- 继续承担责任的具名人类角色。

用这些陈述选择材料并排除无关的视觉复杂度。

### 2. 建立均衡阅读集

依据索引中的 `focus` 和 `structure` 筛选。先选最贴近问题的材料，再加入不同发布者和不同架构家族形成对照。广泛对标时阅读用户要求的 50–100 个独立条目；只做一页聚焦架构时，从已审阅索引中选择更小的任务集。

为每份入选材料记录：

| 字段 | 用途 |
|---|---|
| `source_id` | 回链到已审阅索引 |
| `question_answered` | 该材料为什么进入任务集 |
| `relationship_grammar` | 层次、流向、边界、控制、循环或所有权 |
| `useful_move` | 值得适配的关系 |
| `non_transferable` | 厂商栈、品牌、原文、图标、媒体或坐标 |
| `decision` | 采纳、改造、对照或搁置 |

### 3. 提取关系证据

面对每张图，先用动词描述结构，再考虑版式：

- 什么进入、什么离开；
- 什么转化成什么；
- 什么同时约束多个阶段；
- 谁拥有定义或决策；
- 不确定性、评估与升级出现在哪里；
- 什么作为反馈返回、哪项资产因此改变。

把不同发布者反复出现的关系聚成簇。只有当一个模式能够解释当前问题，并且脱离厂商产品和原始视觉仍然成立时，才进入综合。

### 4. 选择并组合模式卡

选择：

- 一个确定阅读路径的**主骨架**；
- 一个显露责任的**控制模式**；
- 必要时增加一个解释学习、发布或反馈的**演进模式**。

ChatBI 房子图常用组合是：

- 以“结果—地基房子图”为主骨架；
- 内部放入“证据阶梯”“语义中介核心”和“调查编排循环”；
- 外围放入“横切控制轨”和“人类决策门”；
- 用“受治理反馈飞轮”把经营结果带回版本化资产。

### 5. 从问题推导房子

用七个结构角色作为工作画布：

| 角色 | 推导问题 |
|---|---|
| 屋顶 | 哪个业务结果或决策承诺收束全图？ |
| 楼层 | 哪些能力构成有顺序的转换，而不是名词清单？ |
| 支柱或控制轨 | 哪些控制跨越多个楼层，通过什么机制生效？ |
| 地基 | 哪些共享底座使上层能力可运行？ |
| 上行路径 | 企业现实如何变成意义、证据、判断和行动？ |
| 回流路径 | 实际结果如何修订定义、证据、方法或发布版本？ |
| 决策门 | 哪个具名角色批准、质疑、修订或升级？ |

先画关系图。如果房屋几何比流程、网格或生命周期更能讲清这些关系，再采用房子造型。

### 6. 把关系图转成页面

1. 按管理阅读顺序分配空间：结果、转换、控制、实施。
2. 先规划证据上行路径和反馈回流路径，再放置房间。
3. 让屋顶、楼层、控制轨、地基和决策门承担不同视觉任务。
4. 每层只保留足以证明责任的少量子能力。
5. 使用原生可编辑形状和用户批准的主题。
6. 在讲者备注或任务来源记录中写入来源 ID 与代表性引用。

### 7. 诊断草图

提出以下问题，并先修改关系图再做视觉精修：

- 观众能否解释每一层为何处于当前位置？
- 能否追踪一个事实从来源到行动，再沿反馈路径返回？
- 治理、安全、质量、来源和可观测是否触达其影响的机制？
- 模型贡献与人类责任的边界是否可见？
- 图表达的是当前企业问题，还是一个泛化厂商栈？
- 每个被采纳的视觉思想能否回溯到来源 ID 和模式卡适配？

### 8. 关闭研究账本

记录：

- 最终来源集和模式卡；
- 采纳的关系与舍弃的替代方案；
- 当前任务特有的名称和责任；
- 代表性引用；
- 对被参考作者和团队的感谢；
- 未再分发来源架构图、原文、图标、品牌、母版、主题、媒体或坐标的确认。
