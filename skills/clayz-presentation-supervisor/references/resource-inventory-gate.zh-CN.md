# Logic 前资源盘点门禁

资源盘点属于 Supervisor 根控制面，不是第六个演示文稿阶段。它必须发生在 Logic 前，让用户先知道当前账号和当前主机到底能使用什么，避免质量依赖隐藏资源或模型记忆。

资源盘点开始前，必须先运行 `scripts/component_version_guard.py`，把官方最新 Release 与当前挂载的核心组件逐项对比，并先向用户打印版本表。无法证明最新、任一组件过旧或版本漂移时停止；不得把版本警告降级成普通盘点备注。

## 开工前完成七类扫描

每次新建、修订或审计都要扫描并保留以下七类证据：

1. 已挂载的完整插件运行时与五个治理 Skill；
2. 本次任务输入，包括用户请求以及提供的文档、表格、图片、PPT 和数据文件；
3. 个人 Library 原文件和 Provider 清单，包括原始字节是否真的可读、可哈希；
4. 内置公共 Index 与已登记参考池；
5. 主题、母版、模板、Logo、图标、品牌和其他视觉资产；
6. 当前主机的制作、渲染、检查和目标应用能力；
7. 实际字体环境，包括需要本机复核的延迟验收字体。

个人模式还必须把版本私有学习状态作为 `owner-library` 证据：记录核心版本、学习键、首次学习或复用模式、独立学习审计摘要、持久索引摘要和来源集合摘要。首次运行必须真实读取已准入私有原始字节并构建索引；同版本后续只验证并复用。状态根不可持久化、审计缺失、来源哈希变化或必需学习类型缺失时，不得进入 Logic。

只有定位符、清单记录、模型记忆或不可调用工具都不能算“可用资源”。大型资源池用有名称、有数量、有哈希的汇总项表达，不把数百条记录原样倾倒给用户。

按 `io.clayz.presentation.resource-inventory/1.0` 写出 `ppt-resource-inventory.json`。每项资源都要记录可用性、权利、适用阶段、数量、物化后的指纹、是否选用以及具体理由。使用以下命令完成派生计数、用户摘要哈希和门禁校验：

```bash
python ../../scripts/finalize_resource_inventory.py \
  <resource-inventory-draft.json> <ppt-resource-inventory.json> \
  --brief-output <ppt-resource-inventory-brief.md> --require-ready
```

## Logic 前先告诉用户

在 Provider 物化和制作路线锁定后、任何 Logic、Copy、Art Direction 或 Output 工作开始前，必须发送一条简洁的 commentary 更新，说明：

- 盘点到了什么，按任务材料、个人资源、公共资源、品牌资产、字体和执行能力分组；
- 当前核心组件版本表及官方最新版本；版本门禁必须已经通过；
- 私有学习是本版本首次执行还是复用，学习审计覆盖了哪些知识、模板、规范和方法；
- 本次选用什么以及为什么；
- 哪些不可用、明确不选或仅作条件性备用；
- 已锁定的制作与渲染路线，以及现在开始进入治理后的制作流程。

只使用用户能理解的名称和数量，不暴露私有物理路径、凭据，也不罗列无边界记录。简报中的结构化资源 ID 覆盖必须逐项绑定全部盘点项、已选项、未选项和不可用项；一句泛泛的“已完成盘点”不能通过门禁。此时使用“本次将使用”；“实际使用”留到最终对账。

资源齐全时，发完消息后自动继续，不增加仪式性确认。必需资源缺失或不可访问时，明确列出缺口并在 Logic 前停止；只询问真正需要用户补充的材料或访问选择。不得把个人模式静默切换成公共模式。

## 保持资源锁

Logic 包携带完整资源盘点；Art Direction 和 Output QA 携带其不可变签名。用户在盘点后新增资源时，必须提升盘点修订号、重新锁定，并在使用前再次向用户发送简短更新。

最终监督报告要把开工前每项已选资源对账为“实际使用”或“未使用并说明理由”，以证据覆盖五个治理阶段，并向用户发送简洁的实际使用摘要。任何未出现在盘点中的后加资源不得进入使用记录。
