# Failure Pattern Routing

Failure Patterns are optional, registered diagnostic knowledge. Supervisor may
use one only when the record is human-admitted, hash-current, rights-eligible,
and selected in a Retrieval Receipt for the observed failure signal.

Match the record to actual reopened PPTX objects and rendered evidence. A
rectangle, object count, similarity score, or renderer warning alone is not
quality truth. Record evidence, uncertainty, the earliest preventable stage,
and the repair owner from the registered pattern. Supervisor diagnoses and
routes; it does not perform the repair or own a learning silo.

If no eligible Failure Pattern matches, preserve the issue as task-local
evidence and mark the optional knowledge `unresolved`. Do not invent a failure
code, repair method, or promotion decision.

See `../../../docs/pattern-dataset-library.md`.
