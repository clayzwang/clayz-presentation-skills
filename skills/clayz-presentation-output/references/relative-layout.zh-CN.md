# 相对布局制作合同

本合同把批准的区域关系转成可编辑坐标，不新增构图判断。相对布局树受开源项目 [pom](https://github.com/hirokisakabe/pom) 的 Flexbox/Yoga 思路启发；准确来源与边界见仓库 `provenance/manifest.yaml`。最终交付由中央配置选定的渲染器、主题配置和 Output QA 完成。

## 适用边界

优先使用“固定外框 + 内部相对布局”的混合方式：

- 固定外框：母版继承对象、标题区、动态页码、持续导航、主视觉锚点、语义留白边界；
- 相对布局：批准内容区内部的行、列、12列网格、等权模块、固定栏 + 弹性栏、嵌套区块；
- 绝对定位：连接器、标签引导线、图表遮罩、需要像素级对齐的局部对象。

相对布局只吸收文案换行、同级模块数和内容高度的技术变化。它不得改变 `area_plan`、主骨架、面积权重、阅读动线、主媒介、密度、语义留白或系列持久元素。

## 从艺术指导字段到布局树

| 批准字段 | Output实现 |
|---|---|
| `area_plan` 的12列跨度 | `slide.compose` 的12列 `grid` 与 `columnSpan` |
| 区域面积比例 | 固定轨道、`fill` 或相同比例的弹性轨道 |
| `reading_path` | `row`／`column` 子节点顺序；不得靠坐标交叉改序 |
| `contains_copy_ids` | 一个具名容器包含对应 `COPY::<copy_id>` 对象 |
| `copy_unit_map.render_target_id` | 容器和原生对象使用稳定 `name`，写盘回读时核对 |
| `persistent_elements` | 外框固定坐标；同系列复制同一对象名、尺寸和层级 |
| `semantic_whitespace` | 独立受保护轨道或固定空白框，不参与 `fill` 分配 |
| `progressive_change` | 只增删获准变化的子节点；不重建整个布局树 |

## 渲染器实现顺序

1. 加载中央配置的生成主题或用户指定母版；确定正文安全框 `frame`。
2. 在 `frame` 内用当前渲染器的行、列、网格与图层能力建立布局树。
3. 先固定不可漂移轨道，再把剩余区域交给 `fill`；同级等权对象都用 `fill`，不要逐个手算宽度。
4. 文本容器以批准字号、主动断句和对象名渲染；`hug` 只用于允许随内容增长的局部，不得挤占受保护留白。
5. 图表、表格、图片和连接器继续使用原生／精确对象；必要时读取具名布局容器的边界后定位，不把整页改造成流式网页。
6. 导出布局清单并在最终写盘回读后核对对象名、边界、顺序、重叠和溢出。

## 容量与溢出裁决

禁止开启会静默缩字、缩间距或统一缩放整页的自动适配。发现容量不足时按以下顺序处理：

1. 在批准区域内优化换行、弹性轨道和同构间距；
2. 检查固定轨道是否错误占用可用空间；
3. 生成溢出诊断与布局证据；
4. 回流 Art Direction／Copy／Logic，由上游或用户裁决。

不得缩到 `typography_contract` 下限以下，不得挪用 `semantic_whitespace`，不得擅自删字、换媒介、改面积或拆并模块。

## 诊断与验收

- 同一布局族至少测试“短中文／长中文”和“模块减少／增加”两个变体；
- 最终PPTX必须继续通过配置字体、字形像素、主题或母版继承、目标应用、可读性、对象清单和全稿渲染检查；
- XML中存在中文但最终渲染没有中文字形，属于失败，不得以布局无溢出代替；
- 相对布局引擎的 `NODE_OVERLAP`、`NODE_OUT_OF_BOUNDS` 或无报错结果只作辅助证据，不能替代逐页视觉检查；
- pom 可作为研究、探针和诊断对照，不作为交付引擎，也不得读取现有PPTX后重建主题、母版或字体体系。
