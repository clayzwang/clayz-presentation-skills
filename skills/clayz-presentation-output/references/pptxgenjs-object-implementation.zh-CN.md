# PptxGenJS 对象实现路由

只有当配置后端为 PptxGenJS、未来经过审查的配置已打开安全门，而且批准方案可由支持的可编辑对象实现时，才使用本路由。公开 v0.2.0 因当前间接依赖链存在尚未修复的高危拒绝服务公告而刻意关闭。

Clayz 依据公开的 [PptxGenJS 4.0.1 文档](https://gitbrent.github.io/PptxGenJS/) 维护原创实验适配器。该项目采用 MIT 许可；准确版本、提交、文档、再分发边界和当前安全阻断记录在 `provenance/manifest.yaml` 和 `provenance/THIRD_PARTY_NOTICES.md`。仓库不包含其源码、依赖锁、演示文件、模板、母版或媒体。v0.2.0 适配器会阻断图片/SVG，并要求显式风险确认；它不是生产路线。

## 输入边界

适配器读取 `packages/contracts/render-manifest.schema.json`，它位于批准的 Copy 与 Art Direction 之下，只是技术清单，不是新的创作层。渲染前必须：

- 每个 `object_id` 全局唯一；
- 每个可见批准文案只绑定一个 `copy_id` 和对象；
- 先求解相对布局，再创建对象；
- 素材只能来自已知来源的本地文件或内联数据；
- 后端支持时保持图表和表格原生可编辑；
- 用户已有活动母版时，不另建程序化母版替代它。

文字、形状/线条、表格与图表映射到 PptxGenJS 的公开对象 API；图片/SVG 在 v0.2.0 中安全阻断。对象类型必须服从批准的媒介和语义树，不能把每个文案机械翻译成独立矩形。

## 失败关闭

不要在本公开版本中为不可信或生产输入安装、运行该依赖。当前适配器只保留为通过语法检查的 API 映射，除非维护者另行做出显式风险决定，否则会失败关闭。对象或运行路线被阻断时，应选择安全的已配置后端或如实返回能力缺口，不得静默削弱批准方案。

写盘成功只证明文件被创建。仍须重开最终 PPTX、检查对象名称和类型、在至少一个目标应用中逐页渲染、必要时验证中文像素，并运行偏差、可读性、体积、节奏、Output QA 与 Supervisor 检查。未经实测不得宣称兼容。
